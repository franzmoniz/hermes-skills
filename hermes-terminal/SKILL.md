# Hermes's Terminal

Typing `hermes` (no arguments) always opens the SAME conversation, titled "Hermes's Terminal" and pinned
in the Hermes app, with a 3-line recap of where the user stopped. `hermes-new` = a separate new chat.
Works alone; needs no other skill. Code: `scripts/terminal.py`, installer `scripts/setup.py`.

## Install
1. Check first: `<HERMES_HOME>/hermes-terminal.json` exists and the shell profile has a
   `# >>> hermes-terminal >>>` block -> already installed (run setup again only to update).
2. Copy this folder to `<HERMES_HOME>/skills/hermes-terminal/` if it is not there.
3. Recap (optional, costs one small model call when Hermes closes): ask the user if they want it and
   with which provider/model they accept (`hermes auth list`; a free one if they want zero cost; never a
   paid API without asking). Ask their language.
4. Run with the Python that runs Hermes:
   `python scripts/setup.py --recap-provider <p> --recap-model <m> --language <language>`
   (or `--no-recap`). It backs up the shell profile, adds the shared `hermes` launcher block and this
   skill's block. On Windows, if it warns about the execution policy, ask the user before running
   `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
5. Tell the user to open a NEW terminal and type `hermes`: the first time, their newest conversation
   becomes "Hermes's Terminal" (renamed and pinned).

## How it works
- The conversation is found by title: "Hermes's Terminal" and continuations "#2", "#3" (Hermes adds them
  when it compresses a long conversation); the one with the newest message wins and only it is pinned.
- Recap: written when Hermes closes, and again on the next open if the terminal was closed with the X.
  It is shown above the resumed conversation (Hermes locale overlay `locales/en.yaml`, created and
  removed only by this skill).
- Shared launcher: the `hermes-launcher` block (same code in every skill of this repo that hooks into
  `hermes`) runs steps registered by skills: `before-*`, one `open-*`, `after-*`. This skill registers
  `open-50-terminal`. Other skills can add steps without depending on this one.
- With Hermes Device Sync installed (optional): it copies "Hermes's Terminal" between devices and hands
  an incoming newer copy to `terminal.py adopt`, so `hermes` continues it on any device.

## Commands
`python scripts/terminal.py current` (id), `recap`, `summarize`, `adopt <id>`. Change the title or the
recap: rerun setup with `--title`, `--recap-provider/--recap-model`, `--language` or `--no-recap`.

## Uninstall
Remove the `hermes-terminal` block from the shell profile (keep `hermes-launcher` if another skill
still uses it; without any skill, delete it too), delete `<HERMES_HOME>/hermes-terminal.json` and,
if it starts with "# Generated by hermes-terminal", `<HERMES_HOME>/locales/en.yaml`.

## Pitfalls
- Titles are unique in Hermes: never rename another conversation to "Hermes's Terminal"; use `adopt`.
- Hermes Device Sync older than 0.7.0 had its own `hermes` function: setup refuses and asks to update it.
- PowerShell profile may live under OneDrive; setup asks Windows for the Documents folder.

## Verification
- `python scripts/terminal.py current` prints an id after the first `hermes`; `hermes sessions list`
  shows "Hermes's Terminal"; the Hermes app shows it pinned.
- Exit and type `hermes` again: the same conversation opens, with "Recap:" above it (if enabled).

## Updates (last install step)
If the skill `hermes-skills-updater` is not installed on this device yet, ask the user whether they want to be told about updates of this skill (and the others from this repository) when Hermes starts. If yes, install it from https://github.com/franzmoniz/hermes-skills (folder `hermes-skills-updater`, follow its SKILL.md). Never update a skill without the user's yes.
